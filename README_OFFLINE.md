# 离线化改造说明

> 接续 [README_FORK.md](README_FORK.md)。该文档记录第一阶段的「双色球助手」模块,
> 本文档记录第二阶段的「服务端下线适配」——让原工程的账号、开奖、走势等功能在
> 无服务端条件下继续可用。

## 一、问题

上游工程把几乎全部数据放在自建服务端 `api.icaiwa.com`,该域名已不可访问:

```
$ curl -o /dev/null -w "%{http_code}" https://api.icaiwa.com
000
```

后果:

| 功能 | 表现 |
| --- | --- |
| 手机号注册登录 | 短信验证码发不出,流程走不完 |
| 后端不可达时的错误处理 | 被当成「未授权」,强制跳转到无法完成的登录页 |
| 首页 / 开奖页 | 整页显示「连接超时」 |
| 走势 / 历史 / 详情 | 全部依赖后端预计算数据,空白 |
| 会员 / 充值 / 优惠券 / 专家 / 战绩 / 消息 | 必然失败 |

## 二、方案选择

考虑过三条路线:

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 自建后端 | 跑上游 Spring Cloud 8 模块 + MySQL + Redis + Nacos | **否决**。还要接阿里云短信、穿山甲/快手广告、微信支付,这些第三方服务无法开通;上游服务的主要内容是专家推荐与战绩,算法在服务端,重建成本极高 |
| B. 只保留助手模块 | 隐藏其余所有功能 | 可行但浪费了上游最有价值的本地分析能力 |
| C. 离线化(采用) | 账号改本地档案;开奖数据改官方接口;统计在本地计算 | **采用**。上游的走势、缩水、奖级、统计本来就是客户端算的,只缺数据 |

## 三、已实现

### 1. 本地用户档案替代账号体系

`lib/store/local_profile.dart`

- 首次启动生成 `uid` 与昵称,连同积分、签到记录、会员状态一起存本机
- 不需要手机号与验证码
- 登录页新增「无需账号,直接使用」入口

`lib/routes/intercepts/route_auth.dart`

- 已有本地档案时放行,不再强制登录

`lib/store/user.dart`

- `authUser` 回退到本地档案,界面始终有可展示身份
- `removeLocalAuth` 不再强制跳转登录页

### 2. 开奖数据改走官方接口

`lib/data/official/official_lottery_api.dart`

| 来源 | 彩种 | 接口 |
| --- | --- | --- |
| 中国福彩 | 双色球、福彩3D、七乐彩、快乐8 | `cwl.gov.cn/.../findDrawNotice` |
| 中国体彩 | 大乐透、排列三、排列五 | `webapi.sporttery.cn/.../getHistoryPageListV1.qry` |

`LotteryInfoRepository` 的以下方法增加官方数据源分支:

- `latestLottery` / `latestPeriod` — 最新一期
- `groupLatest` — 开奖页彩种列表
- `latestLotteries` — 最近若干期
- `historyLotteries` — 历史开奖分页(官方接口不支持分页,按需拉取后本地切片)
- `lotteryDetail` — 单期详情(号码 + 各奖级注数与奖金 + 销售额 + 奖池)

### 3. 遗漏数据本地计算

`lib/data/official/local_omit_calculator.dart`

上游的遗漏由服务端预计算下发,现改为按官方开奖记录本地推算,结果结构与原接口一致,
因此走势图页面无需改动:

- 数字型彩种(双色球/大乐透/七乐彩/快乐8):红球与蓝球逐号遗漏
- 位数型彩种(福彩3D/排列三/排列五):各位 0-9 的遗漏

`lotteryOmits` 已接入,连带恢复:号码走势、通用遗漏、排列五遗漏。

### 4. 本地化账号附属功能

| 功能 | 实现 |
| --- | --- |
| 签到 | 本地按日记录,每日 5 积分 |
| 积分 | 本地累计,签到获得 |
| 余额 | 积分映射到优惠券字段,金额类字段固定 0 |
| 会员 | 本地状态,默认未开通 |

### 5. 入口收敛

全工程统一开关 `lib/utils/app_features.dart` 的 `serverFeaturesEnabled`。
置为 `false` 时隐藏必然失败的流程:

- 首页:移除「推荐 / 选号技巧 / 中奖新闻」页签
- 首页功能网格:隐藏 专家PK / 综合分析 / 热点分析 / 臻选牛人 / 整体分析 / 号码预警
- 我的页:隐藏 关注收藏 / 选号攻略 / 邀请赚钱 / 我的订单 / 账户安全 / 反馈建议 与会员服务横条
- 排行与战绩接口失败不再使整页进入错误态

## 五、未完成

| 功能 | 原因 |
| --- | --- |
| 综合分析 / 热点分析 / 整体分析 / 号码预警 | 需要把官方开奖映射成上游 `LottoCensusRepository` 的多级统计结构,工作量大,当前已隐藏入口 |
| 形态走势(`trendOmits`) | 依赖「形态/大小/奇偶/012路」分类遗漏,需要逐个定义分类口径,当前已隐藏 |
| 专家推荐 / 大师 / PK / 战绩 | 算法在服务端,无法恢复,建议永久下线 |
| 充值 / 会员购买 / 优惠券 / 邀请 / 消息 | 依赖支付与短信通道,无法恢复 |
| 中奖新闻 / 选号技巧 | 运营内容,已移除页签 |

## 六、后续如何真正恢复需要账号的功能

如果确实需要账号体系(例如跨设备同步已购彩票),推荐的做法是**自建一个极简后端**,
而不是修复上游的 Spring Cloud 全家桶:

1. 只实现 3 个接口:匿名注册(返回 uid + token)、拉取/上传已购彩票、拉取开奖数据缓存
2. 用 SQLite/Postgres 单表存储,不要 MySQL + Redis + Nacos
3. 把 `AppFeatures.serverFeaturesEnabled` 置回 `true`,并在
   `LotteryInfoRepository` 中保留官方数据源作为兜底

这样既能保留离线可用性,又只增加很小的运维成本。
